# 2026-08-06 工作日志

## 保存竞态修复（App.vue）
- 现象：本地/在线模式快速从笔记 A 切到 B（A 仍有未保存编辑）时，A 的未存内容概率被写进 B（串味/互换），偶尔表现为不变。
- 根因：单一共享 `editorContent` 缓冲 + `runSaveLogic`/`flushSave` 读「活的」`currentNote.value.id` 与 `editorContent.value`。`watch(currentNote)` 先 `flushSave()` 再 `editorContent = B内容`；flush 瞬间 currentNote 已是 B 但缓冲区仍是 A 内容 → `updateNote(B.id, A内容)`。概率来自「切走时 A 是否还有待保存内容」（2s 防抖窗口内才触发）。
- 修复（`src/App.vue`）：引入 `pendingSave = { id, content }` 快照，编辑/撤销/重做发生时捕获「当时的笔记 id + 内容」；`applySave`/`flushSave`/`watch(editorContent)` 一律按快照落盘，不再读切换后的活状态。`handleUndo`/`handleRedo` 去掉 `originContent = prevContent`/`isUnsaved=false` 的手动设置，改为显式建立 pendingSave，避免撤销后切走丢失结果。
- `watch(currentNote)` 顺序不变（先 flushSave 再切缓冲），因 flushSave 现在只写快照（A 回 A），天然安全。
- 构建验证 `.build-verify-savesnap` EXIT 0；临时目录用 PowerShell 强删。
- 核心收益：快速连续 A→B→C 切换，每次都把各自笔记的快照写回自身，互不串味；beforeunload/卸载仍走 flushSave 保快照。

## 保存机制二次重构：按 noteId 隔离的「后台预保存」（取代上面的 pendingSave 单一快照方案）
- 用户验证发现 pendingSave 方案仍有「串味」，并提出新方案：标签栏每篇已打开笔记各自独立预保存，切换笔记不打断旧笔记的计时器，旧笔记在后台继续计时并落盘。
- 新建 `src/stores/useSaveManager.js`：纯计时/单飞逻辑，`Map<noteId,{content,timer,saving}>`；`scheduleSave`/`flushNote`/`flushAll`/`removePending`。持久化与落盘后回调由 App 注入（`initSaveManager({persist, afterSave})`），避免与 store 循环依赖。
- 并发结论（已回答用户）：JS 单线程 → 多笔记计时器串行执行，互不并行；隐患只在「全局共享单一 pendingSave/saveTimer」（已消除）；各自写各自文件/记录安全；唯一危险是同一文件两次同时在途写 → 用 `saving` 单飞 + flush 前 clearTimeout 规避。
- `src/stores/useNoteStore.js` 新增 `persistNote(id, content)`：本地笔记重建 frontmatter 后 `writeFile` 落盘（**根因 C：此前本地编辑内容从未写磁盘**）；在线走 `updateNote`。新增 `updateNoteContent(id, content)` 仅内存即时同步（保证 2s 窗口内切回不显示陈旧）。`closeTab` 关闭前 `flushNote`。
- `src/App.vue`：删除旧的 `pendingSave/saveTimer/applySave/flushSave/DEBOUNCE_DELAY`；`editorContent` watch 改调 `scheduleSave` + `updateNoteContent`，内容改回原值则 `removePending`；`watch(currentNote)` 切走**不再 flush**（旧笔记后台继续），仅重置 originContent/isUnsaved；beforeunload/onBeforeUnmount 改 `flushAll`。
- `src/components/MdEditor.vue`：删除 `isBusy` 提前 return（**根因 B：切到站 B 时若 80ms 内刚在 A 敲过字，对 B 的 setValue 被丢弃 → 编辑器仍显示 A 内容，表现为显示串味**），保留 `val===currentVal` 防回环。
- 关键陷阱：`updateNoteContent`/`updateNote`/`persistNote` 必须**原地改属性**，不能 `noteList.value[idx] = {...}` 替换元素——否则 `currentNote` 计算属性引用变化会每键触发「切换笔记」watch（重置 originContent/isUnsaved、关闭查找面板）。
- `EditorArea.applyPolish` 去掉直接 `updateNote` 调用（改走 emit→editorContent watch→scheduleSave→persistNote，避免本地笔记漏写磁盘 frontmatter）。
- 构建：Windows 回收站后端限制导致 vite 清空 dist 时报 `safe-delete` 失败 → 每次构建前用 PowerShell `Remove-Item -Recurse -Force` 清 dist。EXIT 0（仅 js-yaml 外部化 / gray-matter eval / chunk>500kB 警告）。

## UI 定位修复：文件/编辑/查看菜单 + AI 配置悬浮窗
- 现象：点击编辑器上方「文件/编辑/查看」三个按钮，下拉菜单跑到网页左上角 (0,0)；点击「AI配置」出现的悬浮窗在窄屏/缩放下可能超出右边界显示不全。
- 根因：下拉菜单原本靠模板 ref（`fileMenuRef` 等）传按钮元素给 `togglePanel`，模板 ref 自动解包在不同场景有歧义，易取到 null → 坐标回落到默认的 (0,0)。AI 配置 `FloatingPanel` 用固定默认位置 `{x:100,y:80}`，仅显示时钳制一次，未锚定到按钮，窄屏易贴边。
- 修复（`src/components/EditorArea.vue`）：菜单按钮 `@click` 改用 `(e) => togglePanel(panel, e.currentTarget)`，直接用被点击按钮的 DOM 元素取 `getBoundingClientRect`，彻底消除 ref 解包歧义；删除不再使用的 `fileMenuRef/editMenuRef/viewMenuRef`。AI配置按钮改用 `openAiConfig()` 按按钮坐标算 `aiConfigPos` 并传给 `FloatingPanel` 的 `:default-position`。
- 修复（`src/components/FloatingPanel.vue`）：`watch(visible)` 在显示时先 `position = {...defaultPosition}` 重新锚定，再 `clampToViewport()`，保证 AI 配置面板每次都在按钮下方且钳制在视口内。
- 构建：PowerShell 强删 dist 后 `npm run build` EXIT 0（仅既有警告）。

## AI 配置悬浮窗输入框右侧贴边（box-sizing 根因）
- 现象：AI 配置面板右侧输入框紧贴面板右边框，左侧却有 16px 间距（不对称）。
- 根因：项目默认 `box-sizing: content-box`（同文件 inputPanel 输入框之前单独加了 `box-border` 印证）。`FloatingPanel` 内容区虽有 `px-4`（左右各16px），但 AI 配置输入框用 `w-full + border + p-2` 且**未加 `box-border`** → `w-full` 只算内容宽度，输入框自身边框+内边距加在外面，整体向右溢出盖住右侧 16px 内边距 → 右侧视觉贴边、左侧留空，不对称。
- 修复（`src/components/EditorArea.vue`）：给 AI 配置三个输入框、AI 润色 textarea、查找/替换框补 `box-border`，使 `w-full/flex-1` 把边框与内边距计入宽度，左右间距对称。
